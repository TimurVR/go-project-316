# Hexlet Go Crawler

CLI-инструмент для анализа структуры веб-сайтов и SEO-метрик с настраиваемой глубиной обхода, ограничением скорости и анализом ресурсов.

## Возможности

- **SEO-анализ**: Извлекает title, meta description и теги H1
- **Обнаружение битых ссылок**: Находит и сообщает о битых ссылках (статусы 4xx/5xx)
- **Анализ ресурсов**: Анализирует изображения, скрипты и стили с информацией о размере
- **Настраиваемая глубина**: Контролирует количество уровней перехода по ссылкам
- **Ограничение скорости**: Поддерживает фиксированную задержку и запросы в секунду
- **Логика повторных попыток**: Автоматически повторяет неудачные запросы при временных ошибках
- **JSON-отчёт**: Создаёт структурированные JSON-отчёты со всеми обязательными полями

Глубина обхода (Depth)
Параметр --depth определяет, сколько уровней ссылок будет обходить краулер:

text
Стартовый URL (depth 0)          depth = 0: только корневая страница
    ├── Страница 1 (depth 1)      depth = 1: корень + прямые ссылки
    │       └── Страница 3 (depth 2) depth = 2: до 2 кликов
    └── Страница 2 (depth 1)       depth = n: до n кликов
Как интерпретируется глубина
depth = 0: Анализируется только стартовая страница

depth = 1: Стартовая страница + все прямые ссылки на внутренние страницы

depth = 2: Страницы на расстоянии до 2 кликов от стартовой

depth = n: Страницы на расстоянии до n кликов от стартовой

Как изменить глубину
Глубина задается через флаг командной строки --depth:

bash
# Только корневая страница
./hexlet-go-crawler --depth 0 https://example.com

# Глубина 3 уровня
./hexlet-go-crawler --depth 3 https://example.com
В коде глубина передается через поле Depth структуры Options:

go
opts := code.Options{
    URL:   "https://example.com",
    Depth: 3, // глубина обхода
    // ... другие параметры
}
Важные замечания
Границы домена: Краулер следует только по ссылкам внутри того же домена. Внешние ссылки проверяются на битые, но не обходятся дальше.

Уникальные страницы: Каждый URL появляется в отчёте только один раз, даже если на него есть несколько ссылок.

Ограничение глубины: При достижении максимальной глубины новые страницы не добавляются в очередь обхода.

Досрочное завершение: Если обход прерван (Ctrl+C или таймаут контекста), отчёт всё равно содержит валидный JSON со всеми собранными страницами.

Ограничение скорости (Rate Limiting)
Краулер предоставляет два способа контроля скорости запросов, чтобы не перегружать целевые серверы.

1. Фиксированная задержка (--delay)
bash
# Ждать 200 мс между запросами
./hexlet-go-crawler --delay=200ms https://example.com

# Ждать 1 секунду между запросами
./hexlet-go-crawler --delay=1s https://example.com
2. Запросов в секунду (--rps)
bash
# Ограничение до 5 запросов в секунду
./hexlet-go-crawler --rps=5 https://example.com

# Ограничение до 10 запросов в секунду
./hexlet-go-crawler --rps=10 https://example.com
Правила приоритета
Если указаны оба параметра --delay и --rps, приоритет имеет --rps

Без ограничений скорости запросы отправляются максимально быстро

Ограничение скорости применяется ко всему процессу обхода, а не к отдельным воркерам

Формат параметров в коде
За ограничение скорости отвечают следующие поля структуры Options:

go
type Options struct {
    Delay time.Duration // Фиксированная задержка между запросами
    RPS   float64       // Запросов в секунду (имеет приоритет над Delay)
}
Логика повторных попыток (Retry Logic)
Краулер автоматически повторяет неудачные запросы при временных ошибках. Количество попыток задаётся флагом --retries.

Какие коды ответов приводят к повтору?
Тип ошибки	HTTP статусы	Описание
Сетевые ошибки	-	Отказ в соединении, таймауты, ошибки DNS
Too Many Requests	429	Ограничение скорости со стороны сервера
Ошибки сервера	500, 502, 503, 504	Внутренняя ошибка, bad gateway, сервис недоступен, таймаут шлюза
Как настроить количество попыток
Количество повторных попыток задаётся через флаг --retries:

bash
# До 3 повторных попыток для неудачных запросов
./hexlet-go-crawler --retries=3 https://example.com
В коде это поле Retries структуры Options:

go
opts := code.Options{
    URL:     "https://example.com",
    Retries: 3, // количество повторных попыток
    // ... другие параметры
}
Как работают повторные попытки
При сбое запроса с временной ошибкой краулер ждёт перед повторной попыткой

Если указан --delay, используется эта задержка между попытками

Если задержка не указана, используется экспоненциальная задержка (100мс, 200мс, 400мс и т.д.)

После исчерпания всех попыток финальная ошибка записывается в отчёт

Формат JSON-отчёта
Краулер создаёт JSON-отчёт со следующей структурой:

json
{

  "depth": 1,
  "generated_at": "2024-06-01T12:34:56Z",
  "pages": [

      "depth": 0,
      "http_status": 200,
      "status": "ok",
      "error": "",

      "assets": [

          "url": "https://example.com/static/logo.png",

Описание полей
Верхний уровень
Поле	Тип	Описание
root_url	string	Стартовый URL обхода
depth	integer	Максимальная настроенная глубина обхода
generated_at	string	Временная метка создания отчёта в формате ISO8601
pages	array	Массив обработанных страниц
Объект Page
Поле	Тип	Описание
url	string	URL страницы
depth	integer	Расстояние от корневого URL (0 = корневая страница)
http_status	integer	HTTP статус код страницы

error	string	Сообщение об ошибке (пустая строка, если ошибки нет)
seo	object	SEO-метрики страницы
broken_links	array	Массив битых ссылок, найденных на странице
assets	array	Массив ресурсов (изображения, скрипты, стили)
discovered_at	string	Временная метка обнаружения страницы в формате ISO8601
Объект SEO
Поле	Тип	Описание
has_title	boolean	Найден ли тег title
title	string	Содержимое тега title (если найден)
has_description	boolean	Найдено ли meta description
description	string	Содержимое meta description (если найдено)
has_h1	boolean	Найден ли тег H1

Поле	Тип	Описание
url	string	URL битой ссылки

error	string	Сообщение об ошибке или описание статуса
Объект Asset
Поле	Тип	Описание
url	string	URL ресурса
